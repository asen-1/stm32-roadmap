## 一、先说结论

（三句话：这个问题的现象、根因、解决办法。让人只看这段也拿到价值）

- 单次转换时，每采一个点 CPU 都要 `Start → Poll → Get`，7µs 全耗在等上面；
- 换成 **连续转换 + 循环 DMA** 后，CPU 完全不参与，数组里永远有最近 64 个采样点；
- 中间我一度以为读数偏低是采样时间不够，**实验证明猜错了**，真正原因是电阻不匹配。

## 三、我以为是……

（这里的"错误假设"是文章最值钱的部分）

**假设**：分压读数从昨天的 1999 掉到 1872，是因为 CubeMX 把采样时间从 71.5 周期改成了 1.5 周期。

**理由**：采样电容充电需要时间，时间短了读不准。

---

## 四、怎么验证

改回 71.5 周期，重新测同一块分压：

| 采样时间 | 分压 avg | 3.3V 直连 avg |
|---|---|---|
| 1.5 周期 | 1872 | 4037 |
| 71.5 周期 | **1862** | 4038 |

**几乎没变** → 假设被否定。

---

## 五、真正的根因

算一下就知道：τ = R × C = 500Ω × ~10pF ≈ 5ns，1.5 周期 = 125ns = **25 个 τ**，早就充满了。

真正的偏差来自分压比：

```
实测 1862 / 4038 = 46.1%
理论（两个 1k）   = 50%
若 1k + 1.2k（1.2k 在上）= 1/2.2 = 45.5%  ← 吻合
```

**结论：一颗电阻是 1.2k，不是 1k**（色环：棕黑红 = 1k，棕红红 = 1.2k）。

---

## 六、下次怎么办

- 采样时间 ≥ **8τ** 就够；源阻抗 ≲1kΩ 时 1.5 周期完全可用；
- **源阻抗 ≳10kΩ 才需要加长采样时间**（50kΩ 约需 40 周期）；
- 读数偏离理论值，先查**元件值**，再查代码。
