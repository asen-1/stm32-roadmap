## 一、结论

1. 想验证「输入捕获」，最简单直接的办法是用自己的 PWM 输出接到自己的捕获引脚（自环测试）；
2. 捕获测不出数，先检查通道开对了没；
3. 工程 printf 无法使用，先查 stdio + fputc + MicroLIB 三件套。

---

## 二、实验设计：为什么要「自己测自己」

在 CubeMX 上设置 PA6 引脚输出规定的 PWM 信号，再设置 PB6 引脚为输入捕获。因为 PA6 输出的 PWM 信号可以自己设定频率、占空比等参数，这样一来，输入捕获结果是否正确就很容易判断了。接线方面，只需要拿一根杜邦线把 PA6 和 PB6 接在一起。

## 三、实验过程中踩到的坑

### 1. 通道号写错了

第一版代码编写完成后烧录进小蓝板，串口窗口没有打印任何数据，我一点头绪都没有。我让 DS 检查了我的代码，发现了 CubeMX 里的配置和 Keil 里代码的编写「表里不一」：我配置的是 `TIM4_Channel1`，但代码里打开输入捕获时写成了：

```c
HAL_TIM_IC_Start_IT(&htim4, TIM_CHANNEL_4);
```

打开的是通道四，导致输入捕获功能未能正常运行。

### 2. 新建工程丢了 printf 三件套

修改代码并重新编译下载后，串口依旧没有打印东西。不过这次有了一点思路：第一个坑已经确定输入捕获是没问题的，但串口依旧不打印，于是我把注意力放到负责「串口打印」的部分。

结果发现是我**新建工程**时，把 printf 的三件套搞丢了。这三件套在我自己的理解里分三部分：

1. `fputc` 重定向
2. `#include <stdio.h>` 头文件
3. 魔术棒里 **MicroLIB** 的勾选

### 3. 花括号的错位

这已经是第三四次犯这个错误了。不过很令我疑惑的是：我明明每次编写代码时都有注意花括号，但不知道为什么，莫名其妙就会把代码写到 `while {}` 循环之外去，导致程序跑飞。

### 4. EC11 选不了 Encoder Mode

按配置要求，应该把 `Combined Channels` 选为 `Encoder Mode`。但做完自环测试、想进行编码器测速时，发现 CubeMX 里的 `Combined Channels` 是灰色的，没法选择。

后面才知道：一开始做自环测试时通道 1 已经被占用了，两者互斥，需要先释放。最后我把 Channel 调回 Disable，才得以设置 Encoder Mode。
