# STM32 PWM 驱动 SG90 舵机不转？我一下午踩了三个坑

> 已发布存档：CSDN（2026-11-15）
> 原文：https://blog.csdn.net/yvngboi/article/details/170816188
> 说明：这是发布时的原样存档，不做修改，保留「粗糙的第一篇」用来对比以后的成长。

---

**结论先行：**

- 舵机嗡嗡响但不动，**九成不是代码问题，是供电问题**；
- 小蓝板上的「5V 引脚」，在没插 USB 时**只有 3.3V**；
- 排查顺序由实际现象决定。

---

## 一、面包板的构造让我把 LED 短路了

在进行呼吸灯实验的时候，我接了一条关于 LED 和电阻的串联线路，但当最后一步 GND 插入时，整片芯片直接断电了，打开串口助手，数据却在正常打印，并且串口打印的占空比什么的也都正常，这说明我的配置和代码都是没问题的。

我以为是接触不良亦或是没有复位，于是拔了又插，但几次下来都没有用。在思索一番后我把目光锁定在了电路的连接上——因为我是新手，对于面包板的构造并不清楚，在一番搜索后我了解到面包板的同一列是导通的。结合我自己的电路，我把 LED 的正负极插在了同一列上，这直接导致了 LED 的短路。

**教训**：面包板的电路连接需要跨过中缝插。

---

## 二、呼吸灯不「顺畅呼吸」而是「大口喘气」

在 LED 亮起时我以为实验已经告一段落，但与预想不同的实验现象还是给我上了一课。不同于教程上渐亮渐暗的呼吸灯，我的 LED 是在渐亮之后，「啪」一下就灭掉了。

根据现象排查原因，我发现 LED 的渐亮过程是没有问题的，而是在渐暗的过程中出现了问题。于是我排查了一下关于渐暗功能实现的代码编写，发现确实是代码编写错误了：

```c
if (pwm_dir > 0)
{
    if (pwm_ccr + 10 <= 1000)  pwm_ccr += 10;
    else                     { pwm_ccr = 0; pwm_dir = 1; }   // ← 错在这
}
```

问题在于：PWM 输出到达顶峰之后，我并不是让它缓慢下降，而是直接归 0，电压的突然变化直接导致了 LED 的熄灭。

正确写法：

```c
else { pwm_ccr = 1000; pwm_dir = -1; }   // 到顶 → 反向
```

## 三、舵机嗡嗡响却不转动

在完成呼吸灯实验后，我开始进行进一步的舵机驱动实验。代码编写完并且烧录完成后给芯片上电，但舵机却不转动，靠近时还能听到舵机嗡嗡的响声。

吸取第一个问题的经验，我以为是接线错误，于是核对了舵机三根线（GND、5V、信号线）的连接，结果发现并没有问题。

于是我向 DeepSeek 求助，他给我提供了一个方向：可能供电不足，无法支持舵机转动。

我首先用万用电表测量了 PA6（PWM 输出引脚）和 GND 之间的电压，并没有问题，保持在设定的范围内变化；接着再测量了 5V 引脚和 GND 之间的电压，发现**只有 3.3V**，确定了问题的根源。

我开始思索为什么和如何解决，最终得知：我采用 ST-Link 连接给芯片供电，而且只插 3.3V 引脚，这限制了芯片最高只能输出 3.3V。最后我用一条公对母的杜邦线，把 ST-Link 上的 5V 引脚和舵机连接起来，才完成了供电，舵机才得以转动。
